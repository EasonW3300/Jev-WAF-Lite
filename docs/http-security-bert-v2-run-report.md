# HTTP 请求安全模型 v2：离线运行记录

本记录对应仓库 README 中的 v2 模型和训练流程。模型只用于本地试用和公开数据离线比较；不接入线上拦截。

## 数据固定与限制

数据由 WCP 正常 HTTP 请求、HttpParamsDataset 单类别 payload、CRS RCE 正向规则测试和旧 CSIC/CRS 弱标签构成。WCP 每个浏览文件最多读取前 5,000 条，只保留该文件首个有效请求所在主站点的请求；解压后超过 50 MiB 的 6 个文件未读取，第三方域名请求也排除。这减少了站点混淆与扫描成本，但会造成站点和浏览阶段抽样偏差。站点按注册域近似值分组，不能保证同一企业的不同域名完全隔离。

旧三份拆分曾被查看；v2 仅取其经限额抽样的弱标签作为训练来源。新测试集只来自 WCP 未见主站点与按独立 payload 家族注入的合成攻击。单条“正常”是 WCP 来源声明，不是人工复核真值；合成攻击也未经过目标应用执行验证。23,181 条无法确认类别的旧请求在 `review.jsonl` 中等待复核，不参与训练或指标。

| 集合 | 正常 | SQL 注入 | XSS | 路径遍历 | 其他攻击 | 主站点 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 训练 | 16,662 | 1,827 | 1,737 | 443 | 1,847 | 177 个 WCP 站点 |
| 验证 | 3,313 | 229 | 225 | 82 | 227 | 35 |
| 校准 | 2,558 | 166 | 164 | 46 | 162 | 30 |

上表是**训练时冻结数据**的数量。公开仓库 `data/v2/` 中的是额外脱敏的发布副本，并剔除了 1,100 条历史 CSIC 行，因此公开训练集有 21,416 条，不能与原模型清单中的哈希混用或声称逐字节复现。发布副本自己的数量、来源版本、新旧 SHA-256 和脱敏次数在 `data/v2/report.json`；配对、重复及拆分审计在 `data/v2/audit.json`。四份发布数据的文本、站点内模板与 payload 家族通过程序校验；合成请求都有对应正常模板。

## 硬件短跑

在 M4 Pro 的 MPS 上，以原版 `google-bert/bert-base-cased`、512 token、物理 batch 4、累积 4 和梯度检查点运行 100 个优化步。中位每步 **2.81 秒**；采样到的加速器内存最大约 **4.54 GB**。按旧随机 batch 顺序、全部三轮更新外推约 **11,859 秒（3.3 小时）**，这是含有动态长度差异的粗略估算，不包括各轮验证、最终校准和测试。正式训练使用长度分桶 batch 与评估 batch 16，时间不能直接按此估算断言。

短跑模型第 100 步在验证集、经验误拦率 1% 口径下召回为 0.2097，PR-AUC 为 0.7268。这只是训练管线与资源验证，不是完整训练效果。短跑未对新测试集打分。

## 完整模型与独立测试

正式训练从原版 `google-bert/bert-base-cased` 权重开始，Encoder 与两个任务头共同微调三轮，共 4,224 次优化更新。按验证集的离线召回和 PR-AUC 选择第 3 轮权重，未用测试集选模型。长度分桶后的前 100 步中位耗时 1.59 秒／步，采样到的 MPS 内存最大约 4.49 GB。独立校准集拟合两个头的温度，并以经验误拦率不超过 1% 选出策略阈值 **0.12603**；该集有 2,558 条正常和 538 条攻击请求，阈值处误拦 16 条、漏拦 7 条。

模型与阈值冻结后，对新测试集只评估一次。模型版本为 `bert-security-v2-1791770771`，结果保存在本地模型包的 `test_report.json`，完整训练配置与四份数据的 SHA-256 保存在 `manifest.json`。

按预先规定的离线门槛：误拦率 ≤1%、攻击总体召回 ≥80%、四个样本量达标类别端到端召回各 ≥70%，**本次测试通过**。来源分组报告只含 WCP：正常请求来自 WCP 浏览记录，测试攻击全部是合成注入。因此不能把这些数字解释为真实站点遭遇攻击时的实际识别率。站点内模板分组与 payload 家族隔离降低了直接重复泄漏，但无法消除语义相近请求及合成痕迹的影响。

测试集中 1,684／6,421 条（26.23%）超过 512 token，按统一首尾保留策略截断；最极端样本只保留约 1.41% 原 token。长请求中位数之外的效果可能受截断严重影响，需在后续真实样本审计中单独检查。站点级明细、来源／合成来源明细及 token 统计都在 `test_report.json`。

## 已试用请求与错误分析

10 条人工编写的本地试用请求只作定性分析，不参与训练、校准或正式指标。其中 9 条按预期给出策略动作和主类别；一条普通 SQL `UNION SELECT` 注入候选被放行，拦截分数约 0.10%，低于离线阈值。困难正常样本中的 SQL 词汇搜索、HTML 文本和可规范化的相对路径均被放行。这组小样本暴露了常见 SQL 注入仍可能漏检，不能用测试集高分替代手工案例复核。详情在模型包的 `case_report.json`。

**结论：**当前交付为通过预设公开／合成数据离线门槛的实验模型，可用于本地试用与后续错误分析。真实业务流量的标签、语境、基率、攻击手法和长请求分布尚未验证；不把它标记为已具备可靠的线上自动拦截能力。
